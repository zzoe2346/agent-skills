# 원칙에 맞춘 Todoist 할 일

사용자의 계획 원칙을 실행 가능한 Todoist 작업에 반영한다. 원칙의 원본은 Obsidian 볼트에 두며 이 스킬에는 원칙을 적용하는 절차만 유지한다.

## 매 요청의 기준

1. 이 스킬 폴더의 `scripts/read_principles.py`를 Python 3으로 실행해 현재 원칙을 읽는다. 설치 경로는 현재 스킬 위치를 사용하고 고정하지 않는다. 볼트는 `PERSONAL_RECORD_VAULT` 환경 변수, 스킬 저장소의 `config/local.json`에 있는 `personal_record_vault`, 기본값 `~/repo/personal-record` 순으로 결정한다. 원본은 해당 볼트의 `2_Areas/일상과 회고/운영 원칙.md`다. 스킬에 적힌 적용 예시는 원본과 현재 사용자 지시가 우선한다.
2. 경로가 바뀌었다면 설정된 볼트에서 `rg --files`로 `운영 원칙.md` 또는 `principles.md`를 찾아 확인한다. 설정 파일 오류는 임의의 기본 경로로 무시하지 않는다. 원본을 찾을 수 없으면 그 사실을 알리고, 적용할 기준이 필요한 부분만 질문한다.
3. 연결된 Todoist 도구로 대상 프로젝트와 섹션의 현재 이름·설명을 확인한다. 과거 ID를 고정해서 쓰지 않는다.

## 할 일로 구체화

- 사용자의 대상과 범위를 보존하면서 제목을 행동과 끝낼 결과가 드러나게 다듬는다. 이미 구체적인 제목이면 유지한다.
- 완료 조건이 자명하지 않으면 설명에 짧게 적는다. 맥락·관련 링크·예상 시간도 필요할 때만 넣는다. 자명한 일에 형식적인 설명을 강제하지 않는다.
- 현재 집중 단위는 30분이다. 합리적으로 추정할 수 있으면 기존 제목 규칙 `[n]`을 적용한다. `[1]`은 약 30분, `[2]`는 약 60분이다. 추정치임을 설명에서 밝힐 수 있다.
- 모든 일을 정확히 30분으로 바꾸지 않는다. 사용자가 정한 시간을 보존하고, 크거나 막연한 작업은 명확한 다음 행동이나 자연스러운 하위 작업으로 나눈다. 목표·대상처럼 꼭 필요한 정보만 질문하고, 불필요한 작업·성과·기한을 만들어 넣지 않는다.
- 시간 추정의 근거가 부족하면 숫자를 억지로 붙이지 않는다. 현재 원칙의 집중 단위가 바뀌면 새 기준을 따른다.

예: “이력서 첫 번째 프로젝트 설명 수정할 일 추가해줘” → `[1] 이력서 첫 번째 프로젝트 설명 수정하기`. 설명에는 “문제·본인 기여·성과 근거가 드러나도록 수정한 문단”을 완료 조건으로 적고 예상 30분임을 밝힌다. 사용자가 요청한 대상과 분량은 유지한다.

## Todoist의 현재 운영 방식

사용자가 다른 위치를 지정하면 그 위치를 따른다. 기본 위치는 활성 프로젝트 `할 일`이며 현재 섹션은 `백로그`, `이번 주`, `오늘`, `진행 중`이다. 프로젝트 설명과 현재 원칙에서 변경된 기준이 확인되면 최신 기준을 적용한다.

- 시기 지정 없이 추가하는 일은 `백로그`에 둔다.
- 이번 주에 하기로 고른 일은 `이번 주`, 오늘 실행하기로 고른 일은 `오늘`에 둔다. 실제 시작했다는 뜻이 없으면 `진행 중`으로 옮기지 않는다.
- 이 보드에서 `오늘` 구역과 기한은 서로 다른 의미다. 단순히 오늘 할 일로 고르는 것만으로 만료 날짜를 붙이지 않는다. 실제 마감 또는 사용자가 요청한 날짜·시간·반복 일정이 있을 때 해당 날짜 필드를 사용한다.
- 날짜 계산은 사용자의 현재 날짜와 시간대(Asia/Seoul)를 기준으로 한다. `dueString`은 실행 날짜·시간·반복 일정, `deadlineDate`는 명시된 고정 마감이라는 도구의 의미를 지킨다. 현재 제공되는 스키마와 계정 기능을 확인한다.
- 우선순위와 라벨은 사용자 지시와 기존 운영 방식을 따른다. 새로운 규칙을 임의로 추가하지 않는다.
- 하루 계획을 요청받았을 때는 기존 `오늘` 작업의 예상 시간을 포함해 총량을 계산하고, 알려진 가용 시간과 여유를 고려한다. 가용 시간을 모르면 임의의 시간 예산이나 고정 작업 개수 제한을 만들지 않는다.
- 덜어낼 일까지 검토하라는 원칙은 계획·검토의 판단 기준이다. 단일 작업 추가 요청으로 기존 작업의 삭제·완료·보관·일괄 재배치를 수행하지 않는다.

## 입력과 확인

설치된 Todoist 연결 도구를 사용한다. 프로젝트·섹션 탐색에는 `find_projects`, `find_sections`, 관련 중복 확인에는 `find_tasks`, 생성에는 `add_tasks`, 필요한 생성 결과 재확인에는 `fetch_object`를 사용한다. 도구 이름의 접두사와 인자 스키마는 현재 환경에서 확인한다.

- 사용자가 추가를 요청했고 필수 정보가 충분하면 반복 확인 없이 실행한다. 추천·초안·원칙 논의만 요청했으면 실제 작업을 생성하지 않는다.
- 관련 제목과 대상 범위에서 기존 작업을 좁게 조회한다. 같은 목적의 미완료 작업이 이미 있다면 중복 생성하지 않고 해당 작업을 알려준다. 이름만 비슷한 다른 작업은 구분한다.
- 여러 작업은 현재 `add_tasks` 한도에 맞춰 묶는다(확인 시점에는 최대 25개). 응답의 성공·실패와 생성 ID를 확인한다.
- 응답이 불명확하거나 일부만 성공하면 성공한 작업을 재생성하지 않는다. 대상 프로젝트에서 존재 여부를 확인하고, 확인되는 미생성 항목만 재시도한다. 존재 여부를 판단할 수 없으면 무작정 반복 입력하지 않고 확인이 필요한 상태를 알린다.
- 결과는 생성한 제목·위치·기한 또는 일정·예상 시간 중 관련 정보와 작업 링크로 짧게 보고한다. 도구가 확인하지 않은 성공을 주장하지 않는다.
